# WeChat Official Account Agent Kit

Portable starter kit for connecting an AI/agent harness to a WeChat Official Account (微信公众号 / 服务号) using the **passive reply** webhook flow.

This repository is intentionally **not LingTai-specific**. It ships:

- an agent-readable `SKILL.md` playbook;
- small Python helpers for signature verification, XML parsing, passive replies, access-token cache, and customer-service messages;
- a minimal FastAPI webhook template;
- examples for LingTai and generic agent harnesses;
- distilled reference notes from the official WeChat docs.

## Why this repo exists

WeChat has multiple product surfaces that look similar but behave very differently:

| Surface | Good for | This repo? |
|---|---|---|
| Personal WeChat / iLink client | fast personal-account integration, dev experiments | No — see `lingtai-wechat` |
| Official Account passive reply | public-account chatbot, immediate replies to user messages | **Yes** |
| Official Account customer-service API | async replies after user interaction | Phase 2 helpers included |
| WeCom / 微信客服 | enterprise/customer-service operations | Adjacent, not primary |

The passive-reply path is the cleanest MVP for an official-account AI assistant: user sends a message → WeChat POSTs XML to your server → your server returns reply XML within 5 seconds.

## Quickstart

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[server]'

export WECHAT_MP_TOKEN='choose-a-random-token'
export WECHAT_MP_APPID='optional-for-phase2'
export WECHAT_MP_APPSECRET='optional-for-phase2'

uvicorn templates.fastapi_wechat_mp:app --host 0.0.0.0 --port 8000
```

Expose the server over public HTTPS (ngrok, Cloudflare Tunnel, a real reverse proxy, etc.) and configure your Official Account backend URL:

```text
https://<your-domain>/wechat/mp/webhook
```

In the Official Account backend configure:

- URL: the HTTPS webhook above
- Token: same value as `WECHAT_MP_TOKEN`
- EncodingAESKey: random/generated by platform (safe mode support is a later phase)
- Message encryption mode: plaintext for first MVP, safe mode later

## MVP behavior

The template implements:

- `GET /wechat/mp/webhook`: verifies `signature/timestamp/nonce` and echoes `echostr`.
- `POST /wechat/mp/webhook`: verifies signature, parses XML, handles text messages, and returns text XML.
- 5-second discipline: the template is structured so you can return `success` for slow tasks and queue background work.

## Official constraints to design around

- Passive reply is **not JSON**. It is XML returned as the HTTP response body.
- WeChat expects a response within **5 seconds**. If not, it disconnects and retries; total retries are 3.
- If you cannot finish within 5 seconds, return `success` (recommended) or an empty string to suppress retries and avoid user-facing “公众号暂时无法提供服务”.
- Dedupe message retries by `MsgId`; dedupe events by `FromUserName + CreateTime`.
- Passive media replies require a pre-uploaded `MediaId`; start with text-only.
